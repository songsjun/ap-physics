## 一、架构分层

四层架构，依赖方向严格单向（只允许上层依赖下层）：

```
┌──────────────────────────────────────────────────────────┐
│  Layer 4: Presentation                                    │
│  Pages(DayPage, DashboardPage, SettingsPage)              │
│  Components(ResourceCard, FeedbackCard, ProgressBar)      │
│  Adapters(ExternalCard, QuizCard, AIGradedCard, Checklist)│
└────────────────────────┬─────────────────────────────────┘
          dispatch Command│read FlowState
┌────────────────────────▼─────────────────────────────────┐
│  Layer 3: Application                                     │
│  DaySessionManager · assembleDaySnapshot · ShareService   │
└──────┬──────────────────────────────────────┬────────────┘
       │ calls domain modules                  │ calls infra
┌──────▼──────────────────────────────────┐  ┌▼─────────────────────────────┐
│  Layer 2: Domain                        │  │  Layer 1: Infrastructure      │
│  LearningFlow (pure)                    │  │  IRepository → DexieRepository│
│  ContentCatalog (read-only)             │  │  AIService                    │
│  ProgressTracker (read/write)           │  │  StorageService               │
│  AdaptiveEngine (pure)                  │  └──────────────────────────────┘
└──────────────────────────────┬──────────┘
                               │ depends on IRepository interface (not impl)
┌──────────────────────────────▼──────────────────────────┐
│  Layer 0: Foundation                                     │
│  types.ts (all shared TypeScript types)                  │
│  constants.ts                                            │
└──────────────────────────────────────────────────────────┘
```

**依赖规则**：
- Presentation → Application（只通过 Command/FlowState 接口）
- Application → Domain + Infrastructure
- Domain → IRepository 接口（不 import DexieRepository）
- Infrastructure 不依赖 Domain
- Foundation 不依赖任何层

## 二、模块目录

### Layer 0 — Foundation

#### `types.ts`
- **职责**：所有跨层共享的 TypeScript 类型定义，零逻辑
- **输出**：`Resource`, `KnowledgePoint`, `Completion`, `CompletionResult`, `FlowState`, `Command`, `DaySnapshot`, `DayStats`（见第四节）

#### `constants.ts`
- **职责**：全局业务常量，单一来源
- **内容**：
  ```typescript
  export const PASS_THRESHOLD = 0.75    // computeFlowState 和 shouldUnlock 均从此导入，不重复定义
  export const LIBRARY_VERSION = '1.0.0' // seedContentLibrary 版本标记
  export const WEEKS = 8
  export const DAYS_PER_WEEK = 7
  ```

### Layer 1 — Infrastructure

#### `StorageService` (`lib/storage.ts`)
- **职责**：所有 localStorage 操作的统一入口，防止 key 散落
- **入口**：`userId.get()` / `userId.init()` / `apiKey.get()` / `apiKey.save()` / `apiKey.clear()`
- **输入**：无（读）/ string（写）
- **输出**：string | null
- **副作用**：读写 localStorage

#### `IRepository` + `DexieRepository` (`lib/repository/`)
- **职责**：数据持久化的抽象层，隔离 IndexedDB 实现细节
- **入口**：`repo`（全局单例，export const repo: IRepository = new DexieRepository()）
- **输入**：查询参数（week/day/userId 等）/ 数据对象
- **输出**：`Promise<数据>`
- **约束**：Domain 层只 import IRepository 接口，不 import DexieRepository

#### `AIService` (`lib/ai.ts`)
- **职责**：封装 Claude API 调用，提供类型化的 AI 功能
- **入口**：`gradeCalculation(question, reference, answer, onChunk?)` / `getDailyFeedback(concepts, stats)`
- **输入**：题目/答案/学习统计
- **输出**：`Promise<GradeResult>` / `Promise<DailyFeedback>`
- **副作用**：网络请求（Anthropic API）
- **约束**：Key 从 StorageService 获取；无 Key 时抛 `ApiKeyMissingError`，调用方处理降级

### Layer 2 — Domain

#### `ContentCatalog` (`lib/domain/catalog.ts`)
- **职责**：资源和知识点的只读查询
- **入口**：
  - `getDay(week, day, tier): Promise<Resource[]>`（按 slot_order 排序）
  - `getKP(id): Promise<KnowledgePoint | null>`
  - `getBCandidates(conceptIds, seenIds): Promise<Resource[]>`（B 层未见资源）
- **输入**：week/day/tier/conceptIds/seenIds
- **输出**：资源或知识点数组
- **约束**：**只读，无任何写操作**；依赖 IRepository

#### `ProgressTracker` (`lib/domain/progress.ts`)
- **职责**：完成记录写入；解锁判断委托给纯函数 `shouldUnlock()`
- **入口**：
  - `record(userId, resourceId, result): Promise<void>`（只写 completion，不判断解锁）
  - `unlockDay(userId, week, day): Promise<void>`（单独写 day_unlocks）
  - `getDayStats(userId, week, day, totalACount: number): Promise<DayStats>`（totalACount 由调用方传入，避免事务内跨表读 resources）
  - `getAllProgress(userId): Promise<ProgressSnapshot>`
- **输入**：用户行为结果（CompletionResult）+ 上下文（week/day）
- **输出**：`DayStats` / `ProgressSnapshot`
- **副作用**：使用 **Dexie 事务** 保证 completion + unlock 写入的原子性
  ```typescript
  // Application 层调用方式（DaySessionManager）：
  await db.transaction('rw', db.completions, db.day_unlocks, async () => {
    await tracker.record(userId, resourceId, result)
    const stats = await tracker.getDayStats(userId, week, day)
    if (shouldUnlock(stats)) await tracker.unlockDay(userId, nextWeek, nextDay)
  })
  ```
- **SRP 决策**：`shouldUnlock(stats: DayStats): boolean` 是纯函数，放在 `lib/domain/flow.ts`，业务规则（75% 阈值）集中管理

#### `shouldUnlock` (`lib/domain/flow.ts` 中的纯函数)
- **职责**：判断是否满足解锁条件
- **入口**：`shouldUnlock(stats: DayStats, mode: DayMode): boolean`
- **输入**：DayStats + 当天模式
- **输出**：boolean
- **规则**：STANDARD 模式 `passRate ≥ PASS_THRESHOLD(0.75)`；REVIEW 模式所有资源完成即解锁

#### `LearningFlow` (`lib/domain/flow.ts`)  ← **纯函数**
- **职责**：从当天数据快照计算"现在该做什么"
- **入口**：`computeFlowState(snapshot: DaySnapshot): FlowState`
- **输入**：`DaySnapshot`（见第四节）
- **输出**：`FlowState`（见第四节）
- **约束**：**零 I/O，零 async，零副作用**；完全可测（传入快照，断言输出状态）
- **决策逻辑**（规则顺序不可改变，优先级从高到低）：
  1. `!isUnlocked` → `LOCKED`
  2. 有未完成 A 层资源 → `PRESENTING`（slot=已完成数+1, total=A层总数）
  3. 所有 A 完成 + `mode === 'REVIEW'` → `COMPLETE`（复习周跳过 passRate 检查）
  4. 所有 A 完成 + `passRate ≥ PASS_THRESHOLD` → `COMPLETE`
  5. 所有 A 完成 + `passRate < PASS_THRESHOLD` + `bCandidates.length > 0` → `REMEDIATION`
  6. 所有 A 完成 + `passRate < PASS_THRESHOLD` + `bCandidates.length === 0` → `NEEDS_RETRY`

  **为什么不会死循环**：每次 Command 执行后 Application 层重组 snapshot，已完成的 B 资源被 seenIds 过滤，`bCandidates` 自然缩减至空。状态单调递进，不存在 REMEDIATION → 重算 → REMEDIATION 的回路。`isRemediationExhausted` 标志是冗余的——`bCandidates.length === 0` 已包含全部信息，且纯函数不能改变输入。

#### `AdaptiveEngine` (`lib/domain/adaptive.ts`)  ← **纯函数**
- **职责**：从 B 层候选中按相关性排序，决定优先展示哪些
- **入口**：`prioritize(weakConcepts: string[], bCandidates: Resource[]): Resource[]`
- **输入**：弱点概念列表 + B 层候选资源（已过滤"已见过"）
- **输出**：优先级排序后的 Resource 数组
- **算法**：资源的 `concepts` 数组与 `weakConcepts` 的交集越大排越前
- **约束**：**纯函数**，无数据库访问；`bCandidates` 的"已见过"过滤由 ContentCatalog 完成

---

### Layer 3 — Application

#### `assembleDaySnapshot` (`lib/app/snapshot.ts`)  ← **显式数据流**
- **职责**：按确定的顺序拉取数据，组装 DaySnapshot
- **入口**：`assembleDaySnapshot(userId, week, day): Promise<DaySnapshot>`
- **执行顺序**（依赖顺序不可乱）：
  1. `catalog.getDay(week, day, 'A')` → aResources
  2. 从 completions 表批量获取 → completions Map
  3. `tracker.getDayStats()` → stats（含 weakConcepts）
  4. `catalog.getBCandidates(stats.weakConcepts, seenIds)` → bCandidates（用第3步结果）
  5. `engine.prioritize(weakConcepts, bCandidates)` → 排序后 bCandidates
  6. 组装并返回 DaySnapshot
- **设计意图**：把数据依赖顺序显式化，避免 DaySessionManager 内部隐式排序

#### `DaySessionManager` (`lib/app/session.ts`)  ← **有状态编排者**
- **职责**：管理单次学习会话的状态机；是 UI 与业务逻辑的唯一接口
- **入口**：
  - `load(userId, week, day): Promise<FlowState>`（初始化会话）
  - `execute(command: Command): Promise<FlowState>`（处理用户操作）
  - `requestFeedback(): Promise<DailyFeedback>`（单独的 AI 调用，不触发状态重算）
- **Command Router**（`execute` 内部分发，每种 Command 独立 handler）：

| Command | Handler 职责 |
|---------|-------------|
| `COMPLETE_RESOURCE` | [事务] tracker.record() + getDayStats() + shouldUnlock() + unlockDay() → 重组 snapshot → computeFlowState |
| `SKIP_RESOURCE` | [事务] tracker.record(skipped) → 重组 snapshot → computeFlowState |
| `REQUEST_FEEDBACK` | 调 AIService → 更新 feedback state，**不重算 FlowState** |
| ~~`EXPAND_C_TIER`~~ | 已移出 Command，改为组件内 `const [cExpanded, setCExpanded] = useState(false)` |

- **输出**：每次 `execute()` 都返回最新 `FlowState`
- **状态**：持有 `currentSnapshot` 缓存，Command 执行后更新

#### `ShareService` (`lib/app/share.ts`)
- **职责**：进度导出与分享链接生成
- **入口**：`exportJson(userId)` / `createShareLink(userId): Promise<string>`
- **输入**：userId
- **输出**：触发文件下载 / 返回分享 URL

## 三、主流程（严格单向）

```
用户操作
    │
    ▼
[Presentation] dispatch(command)
    │                               ┌── 异步等待
    ▼                               │
[DaySessionManager.execute(cmd)]    │
    │                               │
    ├─1─ [CommandRouter 分发]        │
    │                               │
    ├─2─ [Dexie transaction] ← 唯一写操作，最先执行，原子性保证
    │         └── tracker.record()           → repo.saveCompletion()
    │         └── tracker.getDayStats()      → 读 completions（事务内）
    │         └── shouldUnlock(stats, mode)  → 纯函数判断
    │         └── tracker.unlockDay()        → repo.unlockDay()（条件执行）
    │
    ├─3─ assembleDaySnapshot(userId, week, day)
    │         └── catalog.getDay()          [读]
    │         └── repo.getCompletions()     [读]
    │         └── tracker.getDayStats()     [读]
    │         └── catalog.getBCandidates()  [读，依赖上一步的 weakConcepts]
    │         └── engine.prioritize()       [纯函数]
    │
    ├─4─ LearningFlow.computeFlowState(snapshot)   [纯函数]
    │
    └─5─ 返回 FlowState
              │
              ▼
    [React useReducer] dispatch({ type: 'SET_FLOW', payload })
              │
              ▼
    [Context] FlowState 更新 → 组件重渲染

    ────────────────────────────────────
    数据流向：用户 → Command → 写 → 读 → 纯计算 → UI
    无任何反向依赖，UI 不直接写数据
```

## 四、核心数据契约

```typescript
// lib/types.ts

// ── FlowState：LearningFlow 的输出，UI 渲染依据 ──
// 注意：LOADING / ERROR 不属于业务状态机，由 React 层独立管理（见第六节）
export type FlowState =
  | { phase: 'LOCKED' }
  | { phase: 'PRESENTING'                                      // 展示 A 层资源
      resource: Resource
      slot: number                                             // 当前序号（A层内，从1开始）
      total: number                                            // A层总资源数
    }
  | { phase: 'REMEDIATION'                                     // 展示 B 层补救
      resources: Resource[]
      slot: number                                             // 已完成 B 资源数
      total: number                                            // 本轮 B 候选总数（首次进入时锁定）
    }
  | { phase: 'NEEDS_RETRY' }                                   // B层耗尽仍未达标，无 attempts（无跟踪机制）
  | { phase: 'COMPLETE'; passRate: number }

// ── Command：Presentation 层唯一可以发出的操作 ──
// EXPAND_C_TIER 是纯 UI 状态（无 DB 写入），不走 DaySessionManager，由组件本地 useState 管理
export type Command =
  | { type: 'COMPLETE_RESOURCE'; resourceId: string; result: CompletionResult }
  | { type: 'SKIP_RESOURCE'; resourceId: string }
  | { type: 'REQUEST_FEEDBACK' }

// ── DayMode：影响 LearningFlow 的判断逻辑 ──
export type DayMode = 'STANDARD' | 'REVIEW'   // REVIEW = Week 8 复习周

// ── DaySnapshot：LearningFlow 的输入，由 assembleDaySnapshot 构建 ──
export interface DaySnapshot {
  isUnlocked: boolean
  mode: DayMode                               // STANDARD（Week 1-7）/ REVIEW（Week 8）
  aResources: Resource[]                      // 按 slot_order 排序
  completions: Map<string, Completion>        // resourceId → Completion
  bCandidates: Resource[]                     // 已排序的未见 B 层资源（空即代表耗尽，无需额外标志）
  bTotalForSession: number                    // 本次会话首次进入 REMEDIATION 时的 B 候选总数（用于进度条）
}

// ── DayStats：ProgressTracker 的读输出 ──
export interface DayStats {
  // passRate = passedCount / gradedCount
  // gradedCount = passedCount + failedCount（只计已评分资源）
  // 排除：status='skipped'，或无 Completion 记录（not_started）
  // 特殊情况：gradedCount === 0 时 passRate = 0（避免除零）
  passRate: number                            // [0, 1]，仅基于已评分资源
  passedCount: number                         // status='passed' 的数量
  failedCount: number                         // status='failed' 的数量
  gradedCount: number                         // passed + failed（passRate 的分母）
  totalACount: number                         // A 层资源总数（含未完成/跳过），用于进度条
  weakConcepts: string[]                      // failed 资源的 concepts 并集
  seenResourceIds: Set<string>                // 所有有 Completion 记录的资源（B 层过滤依据）
}

// ── Resource：内容库资源 ──
export interface Resource {
  id: string
  title: string
  url: string | null
  content_body: object | null
  adapter_type: 'external_manual' | 'native_quiz' | 'ai_graded_text' | 'observation'
  type: string
  platform: string
  tier: 'A' | 'B' | 'C'
  // phase 不存储在 content_library.json，在 seedContentLibrary 时从 type/adapter_type 派生并写入 IndexedDB
  // 派生规则（见 lib/domain/catalog.ts）：
  //   adapter_type === 'native_quiz' | 'ai_graded_text'  → 'CHECK'
  //   type === 'exercise'                                 → 'PRACTICE'
  //   其余（video / article / interactive）               → 'LEARN'
  phase: 'LEARN' | 'PRACTICE' | 'CHECK'
  estimated_minutes: number
  concepts: string[]
  week: number
  day: number
  slot_order: number
}

// ── CompletionResult：Adapter 组件的输出（统一格式）──
export interface CompletionResult {
  status: 'passed' | 'failed' | 'skipped'
  score?: number
  score_max?: number
  ai_feedback?: string
}

// ── AI 输出类型 ──
export interface GradeResult {
  status: 'passed' | 'failed'
  step_errors: string[]
  feedback: string
}

export interface DailyFeedback {
  strength: string
  note: string
  preview: string
}
```

## 六、React 集成模式

```typescript
// lib/app/session-context.tsx
'use client'

const DayContext = createContext<{
  flowState: FlowState
  dispatch: (cmd: Command) => Promise<void>
  feedback: DailyFeedback | null
} | null>(null)

export function DayProvider({ userId, week, day, children }) {
  // ① useRef 懒初始化：确保构造函数只执行一次，即使有副作用也安全
  const sessionRef = useRef<DaySessionManager | null>(null)
  if (sessionRef.current === null) {
    sessionRef.current = new DaySessionManager()
  }

  // ② loading 状态与 FlowState 分离：LOADING 不属于业务状态机
  const [loading, setLoading] = useState(true)
  const [flowState, setFlow] = useState<FlowState>({ phase: 'LOCKED' })
  const [feedback, setFeedback] = useState<DailyFeedback | null>(null)

  useEffect(() => {
    setLoading(true)
    sessionRef.current!.load(userId, week, day)
      .then(setFlow)
      .finally(() => setLoading(false))
  }, [userId, week, day])

  // ③ useCallback：dispatch 引用稳定，避免子组件因父级重渲染而重渲染
  const dispatch = useCallback(async (cmd: Command) => {
    if (cmd.type === 'REQUEST_FEEDBACK') {
      const fb = await sessionRef.current!.requestFeedback()
      setFeedback(fb)
      return
    }
    const next = await sessionRef.current!.execute(cmd)
    setFlow(next)
  }, [])  // sessionRef 是 ref，闭包安全，依赖数组为空

  if (loading) return <DaySkeleton />   // ④ 加载中显示骨架屏，不闪现 LOCKED

  return (
    <DayContext.Provider value={{ flowState, dispatch, feedback }}>
      {children}
    </DayContext.Provider>
  )
}

// ⑤ Adapter 子组件加 memo：配合 useCallback，阻断不必要重渲染
export const ExternalCard = memo(function ExternalCard({ resource, onComplete }) { ... })
```

```typescript
// components/adapters/AIGradedCard.tsx — ⑦ streaming teardown 防内存泄漏
function AIGradedCard({ resource, onComplete }) {
  useEffect(() => {
    const controller = new AbortController()
    
    async function runGrading() {
      try {
        const result = await gradeCalculation(question, reference, answer, {
          signal: controller.signal,
          onChunk: (text) => setStreaming(prev => prev + text)
        })
        onComplete({ status: result.status, ai_feedback: result.feedback })
      } catch (e) {
        if (e.name === 'AbortError') return   // 组件已卸载，静默忽略
        // ⑧ AI 失败降级：不阻断主流程
        onComplete({ status: 'skipped', ai_feedback: 'AI 评分暂不可用，已跳过' })
      }
    }
    
    runGrading()
    return () => controller.abort()   // 组件卸载时取消 stream
  }, [question, reference, answer])
}
```

**设计要点总结**：

| 模式 | 问题 | 解法 |
|------|------|------|
| `useRef` 懒初始化 | 每次渲染执行构造函数 | `if (ref.current === null) ref.current = new X()` |
| `loading` 分离 | 初始 LOCKED 闪现 | 独立 `useState(true)`，异步完成后 false |
| `useCallback` dispatch | 子组件频繁重渲染 | 依赖数组为空，配合子组件 `memo` |
| Dexie 懒初始化 | 静态导出时 SSR 崩溃 | `getDb()` 函数，首次调用时初始化 |
| AbortController | Stream 未关闭内存泄漏 | useEffect cleanup 调用 `controller.abort()` |
| AI 失败降级 | AI 错误阻断主流程 | catch 返回 `status: 'skipped'`，不向上冒泡 |

## 七、目录结构（对应架构分层）

```
lib/
```

## 八、关键不变量（实现时必须保证）

| 不变量 | 违反后果 |
|--------|---------|
| LearningFlow 不调用任何 async 函数 | 变成有状态服务，测试必须 mock |
| LearningFlow 不修改输入 snapshot | 纯函数保证破坏，引入隐式状态 |
| Domain 层不 import DexieRepository | 迁移到 PostgreSQL 时 Domain 需修改 |
| 写操作（record）在 computeFlowState 之前执行 | FlowState 看到的是旧状态 |
| Presentation 只 dispatch Command，不直接调 Domain | 业务逻辑散落进 UI 组件 |
| EXPAND_C_TIER 不走 DaySessionManager | 每次 C 层展开触发 5 次 DB 读，毫无必要 |
| assembleDaySnapshot 按固定顺序执行 | weakConcepts 为空 → 查不到 B 层 |
| AIService 调用失败时返回 skipped，不向上冒泡 | AI 错误阻断主流程 |
| record + unlockDay 在同一 Dexie 事务内 | completion 写成功但 unlock 丢失，用户永久无法解锁 |
| getDayStats 通过参数接收 totalACount，不在事务内读 db.resources | 事务范围外访问表，Dexie 报错 |
| passRate 分母 = passedCount + failedCount，排除 skipped/not_started | 未完成资源计 0 分，人为压低通过率 |
| PASS_THRESHOLD 只在 constants.ts 定义 | 阈值散落，修改时遗漏导致行为不一致 |
| Dexie 通过 getDb() 懒初始化，不在模块顶层 new | 静态导出时 SSR 崩溃（indexedDB is not defined）|
| seedContentLibrary 写入后记录 metadata version 标记 | 中途失败后误判已完成，留下残缺内容库 |
| Resource.phase 在 seedContentLibrary 时从 type/adapter_type 派生，不写入 JSON | JSON 需手动维护 202 条衍生字段，与源字段存在同步风险 |

## 九、健壮性设计

### 数据完整性：事务

```typescript
// DaySessionManager — COMPLETE_RESOURCE handler
async handleCompleteResource(userId, resourceId, result, week, day) {
  // snapshot.aResources 已缓存，传入 totalACount 避免事务内跨表读 db.resources
  const totalACount = this.currentSnapshot.aResources.length

  await db.transaction('rw', db.completions, db.day_unlocks, async () => {
    await tracker.record(userId, resourceId, result)
    // getDayStats 只读 db.completions（在事务范围内），通过参数获取 totalACount
    const stats = await tracker.getDayStats(userId, week, day, totalACount)
    if (shouldUnlock(stats, this.currentSnapshot.mode)) {
      const [nw, nd] = nextDay(week, day)
      await tracker.unlockDay(userId, nw, nd)
    }
  })
  // 事务提交后重组 snapshot，确保读到最新写入
  return this.rebuildFlowState(userId, week, day)
}
```

### 内容库初始化：版本标记

```typescript
// lib/queries.ts
const LIBRARY_VERSION = '1.0.0'   // content_library.json 更新时同步改版本号

export async function seedContentLibrary() {
  const db = getDb()
  const meta = await db.meta.get('content_version')
  if (meta?.value === LIBRARY_VERSION) return   // 已是最新版，跳过

  const { concepts, resources } = await import('@/data/content_library.json')
  await db.transaction('rw', db.knowledge_points, db.resources, db.meta, async () => {
    await db.knowledge_points.bulkPut(concepts)
    await db.resources.bulkPut(resources)
    await db.meta.put({ key: 'content_version', value: LIBRARY_VERSION })
  })
}
```

### 启动时数据健康检查

```typescript
// components/AppInitializer.tsx
useEffect(() => {
  async function init() {
    await navigator.storage?.persist()
    await seedContentLibrary()

    // 检测进度丢失：内容存在但进度为空（可能被 Safari ITP 清除）
    const db = getDb()
    const contentCount = await db.resources.count()
    const progressCount = await db.completions.count()
    const unlockCount = await db.day_unlocks.count()

    if (contentCount > 0 && progressCount === 0 && unlockCount === 0) {
      const userId = storage.userId.get()
      if (userId) {
        // 曾经有 userId 但进度为空 → 提示用户导入备份
        showDataLossWarning()
      }
    }
  }
  init()
}, [])
```
